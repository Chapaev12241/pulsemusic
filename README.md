# Pulse

Плеер: https://chapaev12241.github.io/pulsemusic/

Импорт папок: https://chapaev12241.github.io/pulsemusic/import.html

`docs/` — опубликованный интерфейс GitHub Pages. Soledago и Docker One загружаются из `docs/fonts/` относительными путями. Внешних библиотек интерфейса и Google Fonts нет.

`worker/backend.mjs` — сервер аккаунтов, состояния и загрузки музыки. GitHub Pages раздаёт статические файлы; API работает отдельно на Sites/Cloudflare Workers. Binding `DB` — D1, `BUCKET` — R2. SQL-миграция лежит в `drizzle/`. Не публикуйте секреты или токены в репозитории.

Загрузка музыки требует входа. Каждый пользователь получает отдельное облачное хранилище. Импорт идёт последовательно, повторные файлы определяются по SHA-256. Лимит одного файла — 50 МБ. Потоковые ссылки ограничены по времени, поддерживаются HTTP Range для перемотки.

Проверки без сторонних зависимостей, Node 24:

```
node scripts/build-worker.mjs
node scripts/validate-artifact.mjs
node scripts/test-backend.mjs
node scripts/preview.mjs
```

Предпросмотр: http://127.0.0.1:4173. Облачный API разрешает origin опубликованных сайтов; для тестирования аккаунтов используйте опубликованную версию.

Тесты backend проверяют регистрацию, вход из двух сеансов, разделение аккаунтов, загрузку, дубли, подписи медиассылок, HTTP Range и конкурентное сохранение истории/плейлистов. Мобильная вёрстка проверена при ширине 390 px в Chromium; проверка на физическом iPhone/Safari остаётся отдельным этапом.

Исполнитель и название читаются из ID3/MP4/FLAC через локально закреплённый jsmediatags 3.9.7 (MIT, лицензия в `docs/vendor/`). Если тегов нет, используются имя файла и структура папок. Метаданные можно исправить вручную; повторный импорт сохраняет ручные исправления.

Жанры исполнителей определяются по точному имени/алиасу в MusicBrainz, с резервом через iTunes Search API. Неоднозначные совпадения остаются неизвестными. Сервер ограничивает частоту запросов и кэширует каталог. Музыка в каталоги не отправляется, передаётся только имя исполнителя. На странице артиста указан источник метаданных.

`docs/music.js` содержит собственный алгоритм рекомендаций по содержимому: предпочтения жанров и артистов из истории семи дней с уменьшением веса старых событий, любимые треки, штраф за повторы и регулируемая доля открытий. Это рекомендательный алгоритм, а не обученная языковая модель. В историю попадает реальное прослушивание 30 секунд или половины короткого трека; перемотка не считается прослушиванием.

Дополнительная проверка: `node scripts/test-music.mjs`. Анимации используют небольшие слои и учитывают reduced motion; добавлен таймер сна.

## Общий каталог и друзья

Новые файлы, впервые загруженные после выпуска community, появляются в общем каталоге. Старые приватные файлы не публикуются автоматически. Сам каталог и общий поток доступны без входа; плейлисты, история и переписка доступны только через собственный токен. Изменение метаданных чужих файлов запрещено. Публикацию можно скрыть через owner-only API visibility.

Главная показывает запуск вайба, свежие загрузки самых часто слушаемых за последние 14 дней исполнителей, динамические миксы исполнителей и жанровые подборки. Предпочтения имеют временной вес; история и лайки остаются персональными.

Профиль: имя, описание, цвет и символ аватара. Друзья добавляются заявкой через QR/ссылку с UUID профиля и подтверждение получателем. QR генерируется локально библиотекой qrcodejs 1.0.0 с уровнем коррекции H; центр содержит логотип Pulse. Профиль не раскрывает email. Личные текстовые сообщения до 2000 символов разрешены принятым друзьям; обновляются опросом каждые 4 секунды при открытом экране. Это серверный чат с проверками доступа, без заявления о сквозном шифровании.

DJ-режим на поддерживаемых настольных браузерах: equal-power crossfade на 3 секунды и выбор следующего трека по общим жанрам. Это лёгкий алгоритм, не нейросетевое разделение вокала или BPM-сведение. На iPhone наложение отключено ради фонового воспроизведения. Исходные аудиофайлы не изменяются.

Миграция `0001_community.sql` добавляет новые таблицы без изменения существующих аккаунтов. Тесты проверяют запрос/подтверждение дружбы, защиту диалогов от третьего пользователя, персональность плейлистов, общий поток и отсутствие email в публичном профиле.
